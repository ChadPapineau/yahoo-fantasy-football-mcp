## Method

**The deferred-items analysis.** Round 1's integration pass skipped seven hand-offs as product or
architecture decisions (round-1 register, Open items). Each was analysed against the code, the plan
and measurements, and given a decision: close, or defer with a recorded design and a reopen trigger.
The decisions are in the round-1 register's
[Open items](2026-09-30-phase1a-qa-pentest.md#open-items-for-the-owner-not-defects-decisions) and in
[`HANDOFF.md`](../HANDOFF.md) § Decisions made. The analysis found five defects, QA-2-001 to
QA-2-005, all in text or output that the hand-offs touch. Each was fixed with a regression test in
the same commit.

**Mutation check (all five).** On a copy of the tree at `c99a067` (the branch head), each fix's
non-test change was reverse-applied, with its committed tests left in place. The named tests were
run, then the fix was re-applied and the tests run again. Every test was green before the revert,
red after it, and green after the restore. The table below gives the counts.

**The review of the round's own commits** is described in its own section below (QA-2-006 to
QA-2-025).

**The re-verification** (on `main` at `1296c84`). Every fix the two registers list was re-checked by
a pass independent of the one that made it: round 1's 80 and round 2's 25. The fixes were taken in
four batches by area: CLI, config, manual league and tooling (25); analytics, scoring and Skills
(28); the MCP surface, store, sources and crosswalk (27); and round 2's own (25). For each fix the
pass confirmed the fix is present at `1296c84`, reverted its non-test change (by hand where the
commit no longer reverse-applies), ran the named regression tests (red), restored the file byte for
byte (green), and then tried a neighbouring variant of the original input. A fix held when its tests
went red on the revert and neither the original input nor the variant reproduced the defect.
Otherwise it was reopened under its own id. Results: 83 held, 22 reopened (§ Re-verification).

**The second sweep** (on `main` at `1296c84`). Round 1's twelve lenses were run again by three finder
groups:

1. the five penetration-test lenses (prompt injection and untrusted text, input fuzzing and DoS,
   filesystem and secrets, network client and supply chain, SQL and store integrity) and the CLI and
   process lifecycle;
2. scoring by independent re-derivation, analytics, and the live data pipeline;
3. the MCP contract end to end over stdio, the manual league and onboarding, and the Skills, driven
   as user journeys against the built server in fixture mode.

Each group worked in a private worktree or scratch clone. Commit and push probes used a local bare
repository as `origin`, the main checkout was not touched, and `~/.config/fantasy-football-mcp/`
was never read. Test files were run one at a time, and timing was never used as evidence. A finding
counted only with a runnable reproduction and observed output. Each finding was then reproduced and
challenged by an independent pass that tried to refute it (reproduce, then spec and intent). Of 21
findings, 20 were confirmed (one with its severity lowered) and 1 was refuted (§ Second sweep).

**The fix round** (on `build/qa2-fixes`). The 42 items (22 reopened fixes, 20 new findings) were split
by file ownership into seven groups that worked in one checkout at the same time: analytics E2/E3;
analytics E1/E5; scoring, freshness and sources; the recommendation log; config, CLI and the manual
league; dev tooling; and the Skills. For each item the group reproduced the defect first, wrote a
regression test that fails on the current code and asserts the property over varied inputs (not one
value), fixed the root cause, saw the test pass, reverted the fix once (red) and restored it, and ran
the other tests of the files it touched. Each item, or a tight group of items, is its own commit. An
item that needed a product decision, or was too large to fix safely in the round, was deferred with
its reason, the evidence and a reopen trigger instead of being patched. Where a fix needed a change in
another group's file, that part was handed off rather than made (§ Open after round 2).

**CI.** Runs on `build/qa2-fixes` were often cancelled by the next push while the groups were
committing. The run on the branch head `5daa625` completed green: `ci` 37443821415 (lint, typecheck,
test with the coverage gate, process, smoke, pack, supply-chain; process on macOS is
on-demand), `docs` 37443821196 and `secrets` 37443821350.

  the four-folder message above.
- **Status** fixed — commit `8852df5` (one `SYNCED_FOLDERS` list read by the guard and by the
  message, which now names each folder as `~/<folder>`, a prefix as `~/OneDrive*`) · test:

#### QA-2-026 — Commit messages are never scanned by either commit path

- **Severity** medium · **area** tooling · **category** security · **lens** pt-filesystem-secrets
- **Files** `scripts/dev/commit-paths.sh`, `.githooks/` (no `commit-msg` hook), `scripts/dev/scan-secrets.mjs`
- **What** The local guards covered the staged blobs (`scan-secrets.mjs --index`), the author and
  committer address (`--identity`) and conflict-copy names. Nothing read the commit message:
  `commit-paths.sh` passed it straight to `git commit-tree` and pushed, and the pre-commit hook runs
  before the message exists. The message is published metadata, and with ruleset `24558591`
  forbidding force-push a leaked message on `main` can no longer be rewritten away. gitleaks runs only
