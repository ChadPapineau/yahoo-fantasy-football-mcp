From the advocate's §1.4, and what the rulings left alone:

- **Layering and the provider seam** — the domain/provider/source/store split; the seam is now *used* (`ManualLeagueProvider`, `SleeperProvider`), not changed.
- **SQLite over files** — the choice stands; OBJ-09/10/11 changed how it is used (floor, backup API, lock waits, staging), not the choice.
- **Yahoo XML over JSON, the one path builder, the error classifier and its terminal `NOT_PROVISIONED` rule, `oob` as the default auth path, no raw-GET tool, the journal-then-send / never-retry rule** — untouched apart from the network row added to the classifier.
- **The scoring engine** — canonical-name hub, bracket derivation from names, the property set P1–P14; only the failure policy (OBJ-17) and the `basis` stamp (OBJ-04) changed.
- **Refresh in a separate process (D8)** — the separation stands; the wording that the server "only reads" was withdrawn.
- **The confirmation gate itself** — `prepare_*`/`commit_*`, the HMAC-bound ticket, the compare-and-set precondition, the journal states: not withdrawn; its *claim* is now per client and two of its channels changed shape.
- **Also unchanged:** the `ff_` prefix and naming rules; stdio-only transport and the Streamable-HTTP negative; no telemetry; the envelope's `meta` fields, attribution rule and the 20 000-char size budget; the Yahoo cache policy and limiter; the launchd design; the coverage-gate numbers (only the module list grew); the fixture scrub rules; the ten read-only evals; Skills K2–K7 and `apply`'s read-only mode at P0; Phase 2–3 scope apart from the moves noted above; the D1–D10 defaults (D10 reworded, D0 added above them).
